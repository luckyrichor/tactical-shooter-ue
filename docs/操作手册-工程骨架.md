## A 段：建 C++ 工程（约 30–40 min）

### A1　启动编辑器

直接跑 `D:\UE\UE_5.6\Engine\Binaries\Win64\UnrealEditor.exe`，或从 Epic Launcher 启动 5.6.1。

### A2　选模板

`Games` → **Third Person** → 右侧务必切到 **C++**（不是 Blueprint）。

| 选项 | 选 |
|---|---|
| Project Defaults | **C++** |
| Target Platform | Desktop |
| Quality Preset | Maximum（本机 32 核，编辑器里够用） |
| Starter Content | **不要勾** |
| Raytracing | 不勾 |

**Starter Content 不勾的理由**：它会塞进来几百 MB 的示例资产，全是 `.uasset`，第一次提交就把 LFS 仓库撑大，而这些资产对武器／技能／AI 一点用没有。

**为什么是 Third Person 而不是 First Person**：M2 的 GAS 技能表现和 M3 的敌人 AI（巡逻／追击／攻击的状态切换）需要**肉眼能看出来**，第三人称下才看得见角色自己在干什么；而 M1 的武器状态机与视角无关。
代价是：岗位 03/04 对应的游戏是 FPS，第一人称的射击手感这条线不会被覆盖到。

> **这条是设计决策，现在改便宜，建完工程再改很贵。** 你要是更想按 FPS 走，现在说，我们换 First Person 模板——那样 M3 的 AI 验证会麻烦一些，但更贴岗位。

### A3　位置和名字

| 字段 | 填 |
|---|---|
| Project Name | `TacticalShooter` |
| Location（路径） | `E:\WorkPlan\tactical-shooter-ue` |

工程会落在 `E:\WorkPlan\tactical-shooter-ue\TacticalShooter\`。

**为什么套一层**：向导会在所选路径下**新建**一个以工程名命名的目录，而仓库根目录已存在且非空。仓库的 `.gitignore`（`Binaries/` `Intermediate/` `Saved/` `DerivedDataCache/`）不受层级影响，照样生效。

**路径必须短**——`E:\WorkPlan` 就是为此选的。UE 对路径长度敏感，放到 `Documents` 之类的深层目录会撞上 MAX_PATH。工程名不要带空格和中文。

点 Create。UE 会生成工程并**自动编译一次**，然后打开编辑器。

### A4　编译耗时对照

［实测 2026-09-20，同机最小工程］首编 **82 秒**、重编 **38 秒**。你这次带模板代码，会比这个久一些，但**不该是十几分钟的量级**。

明显超时或失败，按这个顺序查：

1. **报内存相关错误** → 先调 `%USERPROFILE%\Documents\Unreal Engine\UnrealBuildTool\BuildConfiguration.xml` 里的 `MaxParallelActions`（现在是 12，往下调到 8 或 6）。32 核但只有 13.7G 内存，**内存先爆，别急着怀疑代码**。
2. **日志里 `not a preferred version` 警告** → **这是 warning 不是 error**，正常现象。5.6 偏好 MSVC 14.38，本机只有 14.44 和 14.51，已知且不处理。
3. **其他失败** → 把完整日志发我。

### A5　提交前先看 `git status`

```powershell
cd E:\WorkPlan\tactical-shooter-ue
git status
```

确认：

- ✅ 有 `TacticalShooter/Source/`、`TacticalShooter/Config/`、`TacticalShooter/Content/`、`TacticalShooter.uproject`
- ❌ **不该**有 `Binaries/`、`Intermediate/`、`Saved/`、`DerivedDataCache/`、`.sln`、`.vs/`

后者要是冒出来了，**先告诉我，别硬提交**——`DerivedDataCache` 能有几十个 G。

再确认 LFS 真的接管了二进制资产：

```powershell
git lfs status
```

`.uasset` / `.umap` 应该出现在 LFS 那一栏里。如果它们被当成普通文件，**停下来告诉我**，这时候修还来得及，提交之后再修要重写历史。

```powershell
git add .
git commit -m "feat: UE C++ third-person project skeleton"
git push
```

首次推送会传 LFS 对象，比平时慢，正常。

## 卡住时

| 症状 | 先看这里 |
|---|---|
| 编译报内存错误 | 调 `MaxParallelActions`（A4 第 1 条） |
| `not a preferred version` | warning，不用管（A4 第 2 条） |
| 找不到 `GenerateProjectFiles.bat` | Launcher 版本就没有，**不是缺东西**；右键 `.uproject` → Generate Visual Studio project files |
| 编译挑错了编译器版本 | `BuildConfiguration.xml` 里 `<Compiler>` 之外还得有 `<CompilerVersion>`，已配好，别删 |
| `git pull` 失败 | 重跑；仍失败查 Clash Verge 的**服务模式**是否启用 |

更多见 `workplan-docs/环境与踩坑记录.md`（第 13 条专门讲编译器锁定那个坑）。
